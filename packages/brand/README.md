# Brand source of truth

`@repo/brand` owns the existing Vkit Orbit name, logo asset, and semantic color
tokens. This extraction preserves the current identity and light palette; it is
not a rebrand or a new dark theme.

## Public entrypoints

```ts
import { brand } from "@repo/brand";
```

The root export is static, browser/server-safe TypeScript. It never imports React,
environment loaders, or an asset bundler. For Vite-rendered UI:

```tsx
import logoUrl from "@repo/brand/logo.png";
import { brand } from "@repo/brand";

<img src={logoUrl} alt={`${brand.name} logo`} width={180} height={180} />;
```

```css
@import "tailwindcss";
@import "@repo/brand/tokens.css";
@import "@repo/components/styles.css";
```

The PNG lives only in `assets/logo.png`, sourced from
`vandor-landing/public/app-logo.png`. It is a white transparent mark; render it
against a contrasting dark surface. The identity story demonstrates this treatment.
Consumers declare `"@repo/brand": "*"` and use package asset resolution, not a
copied asset or the obsolete `/images/app-logo.png` URL. Non-Vite consumers must
use their own asset pipeline; the name export does not promise a deployment URL.

Color values live only in `src/tokens.css`. UI consumers map its semantic CSS
variables to utilities; radius, layout, and component behavior stay outside brand
ownership. Do not duplicate the palette in web or shared components, or create a
second TypeScript color catalog. If a future server OG renderer needs colors,
scope a shared representation/adapter without introducing divergent source values.

Web's `appConfig` derives `appName` and `defaultTitle` from `brand.name`; it still
owns product description, favicon configuration, and repository URL. The existing
favicon remains in web; no new favicon/icon set is generated by this extraction.
SEO helpers and future OG work consume brand identity rather than redefining it.

## Preview and verification

Colocated stories appear under `Brand/Identity`, covering the real logo/name and
color roles. The package's React/Storybook/Vite dependencies support these previews;
production identity itself has no runtime dependency.

Follow [verification policy](../../.agent/verification.md): UI uses Storybook plus
affected native typechecks. Server/config wiring uses typecheck only. Do not run
builds, system tests, Compose, or backend services for verification. Starting or
restarting Storybook requires permission.

```bash
bun --cwd packages/brand run check-types
bun --cwd apps/web run check-types
```
